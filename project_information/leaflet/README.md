# Лифлет сортировщика

`leaflet.pdf` — готовый двухсторонний лифлет: две горизонтальные страницы A4
(297 × 210 мм), которые печатаются на двух сторонах одного листа. Белый фон,
чёрно-белая графика, весь текст от 12 pt. Макет рассчитан на просмотр полного
листа; раскладка под складывание втрое не применялась, поскольку в задании
фальцовка не оговорена.

## Печать

- Бумага A4, горизонтальная ориентация.
- Масштаб 100% / «Фактический размер», без уменьшения под область печати.
- Двусторонняя печать с переворотом по короткому краю.

## Редактирование и сборка

Все исходники лежат рядом, внешние фотографии и дополнительные загрузки
для сборки не нужны:

- `leaflet.tex` — текст и вёрстка обеих сторон; ссылки для QR-кодов.
- `device_sketch.tex` — векторный эскиз, перерисованный по фотографиям сборки.
- `functional_diagram.tex` — функциональная схема связей компонентов.

Нужны XeLaTeX и latexmk (TeX Live / MacTeX), пакеты TikZ, fontspec, babel,
qrcode, hyperref и шрифты DejaVu из TeX Live. Из корня репозитория:

```sh
latexmk -xelatex -synctex=1 -cd project_information/leaflet/leaflet.tex
```

Из распакованного архива:

```sh
latexmk -xelatex -synctex=1 -cd leaflet.tex
```

Для перехода из PDF к исходнику нужен файл `leaflet.synctex.gz` рядом с PDF.
SyncTeX также включён в самом `leaflet.tex`, чтобы он создавался при ручной
сборке без дополнительного флага. После старой сборки без SyncTeX добавьте
`-g` к команде выше, чтобы принудительно пересобрать документ.

В VS Code откройте корень `sorting-warehouse`: настройки `.vscode/settings.json`
включают XeLaTeX, SyncTeX и сборку при сохранении, обходят проблему пути iCloud.
Откройте `leaflet.tex` и выполните `LaTeX Workshop: View LaTeX PDF file`.
В этом просмотрщике переход к строке исходника выполняется через Cmd+click
на macOS (`ctrl-click` в настройках расширения).

После изменения текста нужно заново проверить обе страницы: блоки расположены
по фиксированным координатам. Не уменьшайте шрифт или масштаб рисунков с
подписями: в `prompt.txt` задан минимум 12 pt.

## Источники и принятые решения

- Требования: `../prompt.txt`.
- Описание программы: `../README.md`; спорные сведения сверены с актуальными
  `main.py`, `hardware.py`, `camera.py`, `controller.py` и прошивкой.
- Исходный замысел, ФИО, группа и ментор:
  `../project_proposal_16.09 (1).pdf`.
- Эскиз: семь фотографий в `project_information`, прежде всего общий вид
  `photo_2026-11-12 21.13.18.jpeg`; это иллюстрация сборки без масштаба,
  а не рабочий чертёж с размерами.
- Роли участников и Telegram-канал уточнены пользователем при подготовке.
- GitHub: `https://github.com/blessedBA/sorting-warehouse`, адрес из `git remote`.
- Telegram: `https://t.me/sortirovachka`.

В текущей программе ряд выбирается по массе, ячейка внутри ряда — случайно;
цвет определяется, но пока не влияет на маршрут. Учёта заполнения нет.
Это отражено в лифлете. Драйверы двигателей названы без моделей: проектное
предложение, KiCad и прошивка содержат разные обозначения. Arduino Uno видна
на фотографиях; ESP32 из начального предложения не представлена как текущий
управляющий модуль. Проектные размеры, предел 50 г и неподтверждённые показатели
точности/скорости не объявляются измеренными характеристиками.

Фотографии подтверждают сборку, код — реализацию программных функций.
Материалы не содержат протокола натурных испытаний полного цикла, поэтому
он указан среди оставшихся проверок. Само оборудование при подготовке
лифлета не запускалось. Выдача объектов и учёт заполнения остаются возможными
направлениями дальнейшего развития и в реализованный функционал не включены.

## Проверка результата

PDF собран XeLaTeX. Проверены число страниц, размер A4 landscape, минимальный
размер текста 12 PDF pt, наличие ссылок, читаемость и отсутствие пересечений
в растровом просмотре. Оба QR-кода считаны OpenCV из рендера PDF и содержат
точные адреса выше. Проверка QR не означает проверку доступности репозитория
или канала через Интернет.
